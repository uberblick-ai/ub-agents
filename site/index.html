ub-agents

An autonomous coding loop for GitHub.

Any agent, no server.

brew install uberblick-ai/tap/ub-agents

macOS or Linux. You need git, an authenticated gh, and the agent CLIs you want to run.

What does ub-agents do?

Your agents prepare issues, implement them, review the pull requests and send work back when it needs fixing. When a decision needs a person, they raise a hand and wait. You define the roles and rules; ub-agents handles the handoffs.

Labels are the queue. You start a launcher, and it runs the agent whose label matches each issue or pull request. Put ready on an issue and the implementer picks it up. When it opens a pull request, that PR gets needs-review and the reviewer takes over. You decide what each label means and what happens after each outcome.

The starter workflow begins at needs-preparation: the preparer sends small, clear work to implementation, other work to an issue-reviewer, and work needing several PRs to prepared sub-issues. See how the loop works.

GitHub is the only state. Claims, attempts and outcomes are comments on the issue or PR, so a restarted launcher rebuilds everything from there. Older ones are hidden as outdated, so a thread shows the latest state and stays readable. There is no database and nothing to host.

Agents only take input from your team. Comments from people without write access never reach them, and on a public repository an outside issue or pull request waits until a maintainer starts it. See approvals.

Use the agents you already have. Each role names a CLI such as claude or codex, a model, and instructions that live in your repository.

After a run, agents report missing context, unclear rules and avoidable rework. Use their retros to fix the instructions once, instead of repeating the same correction in every chat.

ub-agents is for engineers and teams of up to a few dozen people with a hacker, hands-on mentality. It gives you full control, without a convoluted setup or cloud infrastructure to run.

Get started

$ cd your-project
$ ub-agents init     # opens the setup wizard; review before Apply
$ ub-agents launch   # runs the loop; q stops after the current run

Run ub-agents init in your project's checkout to set up a working loop from an opinionated starter set: five roles with their instructions, the labels and a merge policy. Launch with it as it is and adjust it over time. The wizard shows every change before applying it; --use-defaults sets up without questions. See the init command guide and installation guide. Review the starter policy and merge the files before launching from a clean default-branch checkout.

A role is a few lines of YAML

implementer:
  runtime: "codex:gpt-6.1-sol:high"
  trigger: [ready, needs-changes]
  outcomes:
    handed-off: {add: [needs-review]}
  instructions: .agents/implementer.md
  worktree: true

Every key has a short page in the configuration docs.

Add loops to go faster

Every launcher works from the same queue on GitHub, and a claim keeps two of them off the same item. There is no coordinator, so more capacity is one more ub-agents launch: on a teammate's laptop, a cloud server or the same machine. On a laptop a loop runs while the laptop is awake; an always-on server keeps it going overnight. Ten loops serve a team of 20 to 30 engineers well. See add more launchers.
